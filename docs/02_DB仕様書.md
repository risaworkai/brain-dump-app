# ブレインダンプアプリ DB仕様書

## 1. 概要

| 項目 | 内容 |
|---|---|
| DB | Supabase（PostgreSQL） |
| 認証 | **なし**（簡易版。anon キーで接続） |
| RLS | **無効**（`disable row level security`） |
| テーブル | **`thought_entries`（新規用）**、**`brain_dumps`（旧データ互換）**、**`categories`（カテゴリマスタ）** |

クライアントは Supabase JavaScript SDK（CDN）を使用する。接続情報（`VITE_SUPABASE_URL` / `VITE_SUPABASE_ANON_KEY`）は次のいずれかでフロントに渡す。

| 環境 | 渡し方 |
|---|---|
| PC（`起動.bat`） | `.env.local` → `server.mjs` が `/env.js` を動的配信 |
| GitHub Pages / `file://` | リポジトリ直下の静的 `env.js`（`.env.local` から `公開用-env更新.bat` で生成） |

フロント（`src/main.js`）は `../env.js`（相対）を優先し、続けて `/env.js` を試す。

## 2. テーブル一覧

| テーブル | 役割 |
|---|---|
| `thought_entries` | **新規保存の正**。種別・タグ・期限（`due_date`）・カテゴリ（任意）・完了フラグを持つ |
| `brain_dumps` | Day2 以前の **旧データ**。一覧表示・編集・削除・完了チェックを互換維持（カテゴリなし） |
| `categories` | **カテゴリマスタ**。メモ投稿・編集時のドロップダウン選択肢を管理 |

## 3. thought_entries

### 3.1 カラム定義

| カラム名 | 型 | 制約 | 説明 |
|---|---|---|---|
| id | uuid | PK, default `gen_random_uuid()` | 識別子 |
| created_at | timestamptz | NOT NULL, default `now()` | 作成日時 |
| updated_at | timestamptz | NOT NULL, default `now()` | 更新日時 |
| record_type | text | NOT NULL, CHECK | `idea` / `ai_consult` / `prompt` / `learning` |
| title | text | NULL 可 | タイトル（任意） |
| content | text | NOT NULL | 本文（必須） |
| tags | text[] | NOT NULL, default `'{}'` | タグ（カンマ区切り入力を配列化） |
| due_date | date | NULL 可 | 期限（任意）。画面では「期限」と表示 |
| category_id | uuid | NULL 可, FK → `categories.id` | カテゴリ（任意）。未設定時は `NULL` |
| is_done | boolean | NOT NULL, default `false` | 完了フラグ |
| derivatives | jsonb | NULL 可 | 将来用（AI 変換結果など）。現行 UI では未使用 |

### 3.2 record_type の値

| 値 | 画面表示 |
|---|---|
| idea | 思いつき |
| ai_consult | AI相談 |
| prompt | プロンプト |
| learning | 学習メモ |

### 3.3 DDL（新規作成）

`docs/create_thought_entries.sql` を Supabase **SQL Editor** に **中身だけ** 貼り付けて実行する（ファイルパスは入力しない）。

### 3.4 due_date 列の追加（既存 DB のみ）

テーブルはあるが `due_date` 列が無い場合、次を実行する。

`docs/add_due_date_thought_entries.sql`:

```sql
alter table public.thought_entries
  add column if not exists due_date date;
```

列追加後、期限付きで **新規保存または更新** した行から一覧に「期限」バッジが表示される。

### 3.5 category_id 列の追加（既存 DB のみ）

テーブルはあるが `category_id` 列が無い場合、**`categories` マスタ作成後** に次を実行する（一括実行用 SQL は下記 5.3 を参照）。

```sql
alter table public.thought_entries
  add column if not exists category_id uuid references public.categories (id) on delete set null;
```

- カテゴリは **必須ではない**（`category_id` は `NULL` 可）。
- マスタ行を削除した場合、参照中のメモの `category_id` は `NULL` になる（`ON DELETE SET NULL`）。
- 一覧表示では `categories.name` を JOIN または別取得して表示する。

## 4. brain_dumps（旧テーブル）

### 4.1 カラム定義（現行アプリが利用）

| カラム名 | 型 | 制約 | 説明 |
|---|---|---|---|
| id | uuid | PK | 識別子 |
| title | text | NOT NULL | タイトル |
| content | text | NOT NULL | 本文 |
| created_at | timestamptz | NOT NULL, default `now()` | 作成日時 |
| is_done | boolean | NOT NULL, default `false` | 完了フラグ（**要追加**。下記 SQL 参照） |

### 4.2 初期 DDL

`docs/create_brain_dumps.sql` を参照（**`is_done` を含む**）。

### 4.3 is_done 列の追加（既存 DB のみ）

**以前の DDL でテーブルを作った場合**に限り、次を実行する。

`docs/add_is_done_brain_dumps.sql`:

```sql
alter table public.brain_dumps
  add column if not exists is_done boolean not null default false;
```

### 4.4 アプリ上の扱い

- 一覧では種別「思いつき」、タグ・期限なしとして表示する。
- 行に **「旧データ」** バッジを付与する。
- **新規 insert は行わない**（新規は `thought_entries` のみ）。
- 編集時は `title` / `content` のみ update 可能。
- カテゴリは **対象外**（`category_id` 列は持たない）。

## 5. categories（カテゴリマスタ）

### 5.1 カラム定義

| カラム名 | 型 | 制約 | 説明 |
|---|---|---|---|
| id | uuid | PK, default `gen_random_uuid()` | 識別子 |
| name | text | NOT NULL, UNIQUE | カテゴリ名（一覧・ドロップダウン表示） |
| sort_order | integer | NOT NULL, default `0` | ドロップダウン表示順（昇順） |
| created_at | timestamptz | NOT NULL, default `now()` | 作成日時 |

### 5.2 リレーション

| 子テーブル | カラム | 親 | 削除時 |
|---|---|---|---|
| `thought_entries` | `category_id` | `categories.id` | `SET NULL`（メモは残す） |

### 5.3 DDL・初期データ（一括）

`docs/20260530_01_categories.sql` を Supabase **SQL Editor** に **中身だけ** 貼り付けて実行する。次を含む。

1. `categories` テーブル作成
2. `thought_entries.category_id` 列追加（FK・インデックス）
3. カテゴリ仮データ 5 件の `INSERT`

再実行時は `create table if not exists` / `add column if not exists` / `ON CONFLICT (name) DO NOTHING` により、既存環境でも安全に実行できる。

### 5.4 アプリ上の扱い

- 新規・編集フォームは `categories` を `sort_order`, `name` 順で取得し、ドロップダウンに表示する。
- 先頭に「未選択」（値 `NULL`）を置き、保存時に `category_id` を送らない／`null` にする。
- 一覧は `thought_entries` のみカテゴリ名を表示する（`brain_dumps` はカテゴリなし）。

## 6. データ移行（任意）

旧データを `thought_entries` に統合する場合:

`docs/migrate_brain_dumps_to_thought_entries.sql` を SQL Editor で実行する。  
実行後も `brain_dumps` は残る。不要なら手動で削除する。

## 7. セキュリティ方針（簡易版）

| 項目 | 方針 |
|---|---|
| ログイン | なし |
| RLS | オフ |
| キー（PC） | anon キーを `.env.local` に保存。Git には含めない |
| キー（仮公開） | `env.js` に同キーを含め GitHub に push（研修・本人のみ想定） |
| 本番運用 | 公開 URL に載せる場合は Auth + RLS への移行を推奨（将来拡張） |
