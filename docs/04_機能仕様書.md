## 3. 共通仕様

### 3.1 バリデーション

| チェック | 条件 | エラー時 |
|---|---|---|
| 本文必須 | trim 後が空 | 保存しない。トースト「本文を入力してください。」 |
| タイトル | 新規 `thought_entries` は任意 | — |
| 旧 brain_dumps 更新 | タイトル空なら `（タイトルなし）` を送る | — |
| 認証パスワード | 6 文字未満 | 保存しない。`alert('パスワードは6文字以上で入力してください。')` |
| 認証メール | `@` を含まない等 | 保存しない。`alert('メールアドレスを正しく入力してください。')` |

### 3.2 内部状態

| 変数 | 説明 |
|---|---|
| `entriesCache` | 一覧の全行（正規化済み） |
| `edit-id` / `edit-source` | 編集対象の id とテーブル名 |
| `supportsIsDone` | 完了チェック表示（現行は常に true） |
| `categoriesCache` | マスタ行の配列（`id`, `name`, `sort_order`） |
| `categoryById` | `id` → `name` の Map（一覧表示用） |
| 認証セッション | Supabase Auth の `session`（`index.html` 表示前に必須） |

行オブジェクトの `_source`: `thought_entries` または `brain_dumps`。  
`thought_entries` 行は正規化時に `category_name` を付与（`category_id` から解決）。

### 3.3 一覧の取得・マージ（F-02）

```
並列実行:
  thought_entries.select('*').order('created_at', { ascending: false })
  brain_dumps.select('*').order('created_at', { ascending: false })

thought_entries エラー → 一覧失敗として終了
brain_dumps エラー → 無視（テーブル無し等）、thought_entries のみ表示

マージ:
  thoughtRows = normalizeRow(各行)
  legacyRows = normalizeLegacyRow(各行)  // 種別=idea, tags=[], due_date は通常 null
  entriesCache = 結合後 created_at 降順ソート
```

### 3.4 一覧の表示順（描画時）

`sortForDisplay`:

1. `is_done === false` を `created_at` 降順
2. `is_done === true` を `created_at` 降順
3. 連結（未完了のあと完了）

その後 `applyFilters`（種別・キーワード）を適用。

## 4. 各機能の詳細

### 4.1 F-01：新規保存

| 項目 | 内容 |
|---|---|
| トリガー | フォーム submit（`edit-id` が空） |
| テーブル | `thought_entries` |
| 送信フィールド | `record_type`, `title`, `content`, `tags`, `due_date`, `category_id`（未選択時 `null`） |
| 成功時 | フォームリセット、F-02 再実行、トースト「保存しました。」 |

`tags` はカンマ区切り文字列を trim し、空要素を除いた配列に変換する。

`due_date` は date 入力の値（`YYYY-MM-DD`）または null。列が無い等の DB エラー時はトーストに `docs/add_due_date_thought_entries.sql` 実行を促す。

一覧描画時、期限は `getRowDueDate(row)` で `due_date` 等を正規化し、ある場合のみ `期限: ` バッジを表示する。カテゴリは `category_name` がある `thought_entries` 行のみ `カテゴリ: ` バッジを表示する。登録日時は `登録: ` プレフィックス付き。

`category_id` 列・`categories` テーブルが無い等の DB エラー時は、トーストに `docs/20260530_01_categories.sql` 実行を促す。

---

### 4.2 F-03：更新

| edit-source | テーブル | 更新フィールド |
|---|---|---|
| 空または `thought_entries` | `thought_entries` | payload 全体 + `updated_at` |
| `brain_dumps` | `brain_dumps` | `title`, `content` のみ（カテゴリは更新しない） |

編集開始時: `thought_entries` は `#category-id` に `category_id` を反映。`brain_dumps` は `#category-field` を非表示。

成功時: フォームリセット、F-02、トースト「更新しました。」

---

### 4.3 F-04：削除

| 項目 | 内容 |
|---|---|
| トリガー | 削除ボタン → `confirm('削除しますか？')` |
| テーブル | `entryTable(row)` |
| 成功時 | F-02（loadEntries） |

---

### 4.4 F-05：完了切替

| 項目 | 内容 |
|---|---|
| トリガー | 完了チェックボックス change |
| thought_entries | `update({ is_done, updated_at })` |
| brain_dumps | `update({ is_done })` |
| 成功時 | キャッシュ更新、`renderList`、トースト |

**エラー例**: `brain_dumps` に `is_done` 列が無い  
→ トーストに `docs/add_is_done_brain_dumps.sql` 実行を促す文言を付与。

---

### 4.5 F-06：フィルタ

| フィルタ | 動作 |
|---|---|
| 種別 | `filter-type` の値と `record_type` が一致する行のみ |
| キーワード | タイトル+本文を小文字化し部分一致 |

フィルタ変更時は `entriesCache` を再取得せず、クライアントで `renderList` のみ実行。

---

### 4.6 F-07：メッセージ・起動チェック

| 条件 | 表示 |
|---|---|
| url/key 未取得 | env-warning: `.env.local` / `env.js` / `起動.bat` / GitHub Pages の案内 |
| 操作成功/失敗 | toast（4.2秒 / エラー12秒） |

---

### 4.7 F-09：カテゴリ取得

| 項目 | 内容 |
|---|---|
| トリガー | 初期化時、再読み込み時（`loadCategories`） |
| クエリ | `categories.select('id, name, sort_order').order('sort_order').order('name')` |
| 成功時 | `categoriesCache` 更新、`populateCategorySelect()` で `#category-id` を再構築（先頭「（未選択）」） |
| 失敗時 | トーストで通知。一覧・保存は継続可能（カテゴリなし扱い） |

---

### 4.8 F-10：カテゴリ付与（保存・更新）

| 項目 | 内容 |
|---|---|
| 対象 | `thought_entries` の insert / update のみ |
| 値 | `#category-id` が空 → `category_id: null`。選択時は uuid |
| 必須 | しない |

---

### 4.9 F-08：テーマ切替

| 項目 | 内容 |
|---|---|
| トリガー | `#theme-select` の change |
| 保存先 | `localStorage` キー `brain-dump-theme`（値: `dark` / `light`） |
| 反映 | `document.documentElement.setAttribute('data-theme', …)` |
| 初期化 | `index.html` のインライン script（FOUC 防止）+ `main.js` の `initTheme()` |

---

### 4.10 F-11：新規登録

| 項目 | 内容 |
|---|---|
| 画面 | `index.html`（`#auth-section`） |
| 実装 | `src/main.js` |
| トリガー | `#signup-form` submit |
| API | `supabase.auth.signUp({ email, password })` |
| 事前チェック | メール形式・パスワード 6 文字以上 |
| 成功時 | `#auth-section` を非表示、`#app-main` を表示（同一 `index.html`） |
| 失敗時 | `alert('新規登録に失敗しました: …')` |

Supabase ダッシュボードで **Confirm email を無効** にすること（メール確認なし）。

| 項目 | 内容 |

### 4.13 F-14：認証状態表示・ガード

## 6. 起動・環境

### 6.1 PC（`起動.bat` + `server.mjs`）

| 手順 | 処理 |
|---|---|
| 1 | `起動.bat` が `.env.local` の存在とキー名を確認 |
| 2 | `node scripts/check-env.mjs` で値の有無を確認 |
| 3 | ポート 5174 の既存プロセスを停止（可能なら） |
| 4 | `node server.mjs` で静的ファイル + `/env.js` を配信 |

ブラウザは **`http://127.0.0.1:5174/`** を開く。

### 6.2 仮公開（GitHub Pages）

| 手順 | 処理 |
|---|---|
| 1 | `公開用-env更新.bat` で `.env.local` → `env.js` を生成 |
| 2 | `env.js` を含め `main` ブランチへ push |
| 3 | `.github/workflows/pages.yml` により GitHub Pages へデプロイ |
| 4 | `https://<user>.github.io/brain-dump-app/` を PC・スマホで開く |

フロントは静的 `env.js`（相対パス）を読み込む。`server.mjs` は不要。

### 6.3 `index.html` 直開き（`file://`）

- リポジトリ直下に有効な `env.js` があれば、ローカルサーバーなしで Supabase に接続できる。
- `env.js` が無い・空の場合は 6.1 / 6.2 と同様に `#env-warning` を表示する。
